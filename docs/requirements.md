# 易交接 HandoverKit —— 需求规格说明书

> 版本：v1.0（2026-11-03）　状态：基线　维护：Lead
> 本文是功能验收的唯一依据。实现与本文冲突时，先改本文再改代码。

## 1. 项目背景与目标

医疗机构/科室的用物（耗材、器械、办公物资）在班次之间需要交接：交班人清点库存并提交交接表，接班人核对种类与数量后确认接收；班次中领用物品需要登记到患者与操作员，并支持事后审计与撤销审批。

**易交接** 把上述线下流程搬到一个可扫码、可追溯、可分团队管理的 Web 系统中，目标：

1. **接班有据**：系统按当前库存自动生成当日清单，接班人逐项核对后确认接收。
2. **用物可追溯**：每次消耗登记到患者、操作员与日期；撤销必须走审批，审批通过后库存自动恢复。
3. **交班有表**：交班前再次核对并提交用物交接表，形成完整交接链。
4. **管理有数**：管理员可按天/周/月/年查看交接记录，按周/月/年分析物品消耗。
5. **多团队隔离**：超级管理员创建团队；每个团队拥有独立的管理员、成员、交接事项与仓库。

## 3. 核心业务流程

### 3.1 扫码进入

1. 每个「交接事项」对应一个用物仓库目录，并生成一个**固定二维码**（URL 含不可猜测的 token）。
2. 二维码生成后不变；只有管理员手动「申请变更」后才生成新 token，旧码立即失效。
3. 扫码后若未登录 → 登录页（登录后回到扫码页）；登录校验通过后才展示具体界面。
4. 扫码页对普通用户提供三个功能页签：**接班核对 / 用物消耗登记 / 交班表**。

### 3.2 接班核对（验收）

1. 接班人打开扫码页，系统按该交接事项当前库存生成/读取「当日交接记录」清单（物品名称、规格、单位、应有数量）。
2. 接班人逐项核对：勾选「已核对」；如数量不符可填写实盘数量与备注（差异会生成异常事件提示管理员处理）。
3. 全部核对完成后「确认接收」，系统记录：接班人姓名、接班时间、验收明细快照。
4. 验收后清单锁定；如确有疑问走线下沟通，由管理员调整物品数据并做异常消耗记录（库存调整流水）。

### 3.3 用物消耗登记

1. 使用物品后再次扫码进入「用物消耗登记」。
2. 选择物品**只能从该交接事项的仓库列表中选**（不可手输）；填写数量。
3. 登记患者信息：姓名、类别（门诊/住院）、登记号、电话（可选）。
4. 记录使用日期（默认当天，支持补登记过去日期）与操作员姓名（默认当前登录用户）。
5. 提交后库存原子扣减并写入库存流水；库存不足时拒绝提交。
6. 支持一次登记多种物品（同一患者、同一操作员、同一日期）。

### 3.4 交班表

1. 交班前打开扫码页「交班表」，系统展示当前库存清单，要求逐项再次核对。
2. 确认无误后提交：记录交班人姓名、交班时间、交接明细快照。
3. 次日（或下一班）接班时，系统按最新库存生成新的当日清单，形成「接收 → 使用 → 交接」闭环。

### 3.5 撤销用物记录

1. 普通用户不能直接撤销；对已生效的消耗记录提交撤销申请（填写原因）。
2. 团队管理员在「撤销审批」中通过或驳回；通过后库存恢复，记录状态变为「已撤销」，库存流水写入恢复流水。
3. 同一条记录同时只允许一个待审批申请；已撤销记录不可再次申请。

### 3.6 异常事件

1. 任何人可上报异常（缺失、损坏、数量不符、其他），可关联交接记录/物品。
2. 团队管理员处置：填写处理结果并标记已解决；库存类问题通过「库存调整」修正并留下流水。

## 4. 功能需求清单

### FR-01 登录与验证码

- 登录页提供：登录名、密码、图形验证码（服务端生成 SVG，一次性、5 分钟有效）。
- 验证码错误、账号密码错误、账号停用分别给出明确提示；同一 IP/账号连续失败限流。
- 登录成功后跳转：普通用户 → 工作台；管理员 → 管理工作台。支持 `?redirect=` 回跳（仅站内路径）。
- 已登录访问登录页自动跳转。

### FR-02 团队管理（超级管理员）

- 团队列表、创建（名称唯一、编码唯一、描述、时区默认 Asia/Shanghai）、编辑、停用/启用、删除。
- 删除保护：团队下存在用户或交接事项时禁止删除，提示先转移/归档。
- 超级管理员可在顶部切换「当前团队」，跨团队查看与操作。

### FR-03 用户管理

- 团队管理员：查看本团队用户；创建成员账号；编辑姓名/手机号/状态；重置密码；删除（无业务记录时）。
- 超级管理员：任意团队；可创建/调整团队管理员与超级管理员。
- 登录名唯一、≥3 字符、字母数字下划线；密码 ≥8 位，需包含字母与数字。
- 停用账号立即无法登录；已登录会话在下一次请求时失效。

### FR-04 交接事项与二维码

- 管理员可创建多个交接事项；每个事项 = 一个独立用物仓库（物品目录与库存独立）。
- 事项字段：名称、编码（可选）、描述、状态。
- 二维码内容：`{站点地址}/scan/{qrToken}`；token 为随机高熵字符串，生成后不变。
- 「申请变更二维码」需二次确认，生成新 token（版本 +1），旧码失效；操作写入交接事项记录。
- 二维码页面支持查看、下载 PNG/SVG、打印。

### FR-05 物品与库存

- 物品字段：名称、规格、单位、分类、当前库存、最低库存预警、存放位置、备注、状态。
- 管理员可新增（可填初始库存，生成入库流水）、编辑、入库（增加库存）、盘点调整（增减库存，必须填原因）、停用/删除（有流水时只能停用）。
- 库存流水：类型（初始/入库/消耗/撤销恢复/调整）、变化量、操作后库存、操作人、关联单号、时间。
- 低库存（≤ 最低库存）在工作台与统计中提示。

### FR-06 交接记录

- 系统按「交接事项 + 日期」生成唯一交接记录；当日首次进入扫码页/记录页时自动生成，清单取当前库存快照。
- 记录状态：待接收 → 已接收 → 已交班。
- 列表支持：按天/周/月/年筛选、按交接事项/状态筛选、分页；展示接收人/时间、交班人/时间、差异数。
- 详情展示：物品清单（应有/实盘/核对状态/备注）、验收信息、交班信息、当日消耗记录、异常事件、撤销申请。
- 接班核对、交班提交均要求逐项勾选；记录保存操作人姓名快照，账号改名不影响历史。
- 管理员可删除「无消耗记录」的空记录；有消耗记录时禁止删除。

### FR-07 用物消耗

- 列表支持按交接事项、日期范围、状态、患者、操作员筛选与分页。
- 新增：患者姓名/类别/登记号/电话（可选）、使用日期、操作员姓名、物品明细（≥1 项）、备注。
- 服务端事务内校验库存并扣减；任一项库存不足则整体失败。
- 撤销申请：原因必填；审批列表仅管理员可见；通过后库存恢复并写流水。
- 已撤销记录在列表/详情中显著标记，不参与统计消耗量。

### FR-08 数据统计（管理员）

- 时间粒度：本周 / 本月 / 本年（可切换锚点日期）。
- 指标卡：消耗总量、消耗品类数、使用记录数、待审批撤销、未解决异常、低库存物品数。
- 图表：按日/周消耗趋势、按物品消耗排行（数量与次数）。
- 明细表：物品、规格、单位、消耗数量、使用次数、占比。
- 可按交接事项筛选；超级管理员可按团队筛选。

### FR-09 异常事件

- 上报：类型、严重程度、描述、关联物品/记录（可选）。
- 列表与状态筛选；管理员可处置并填写解决说明。

### FR-10 扫码页（移动优先）

- 三个页签：接班核对、用物消耗登记、交班表。
- 顶部展示交接事项名称、团队、当前日期、当前状态（待接收/已接收/已交班）。
- 未登录时先登录（回跳保持 token）；无权限用户提示联系管理员。
- 操作完成后给出明确成功反馈并刷新状态。

## 5. 非功能需求

| 类别   | 要求                                                                                                                                       |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 安全   | 密码使用 Better Auth scrypt 哈希；会话 HttpOnly Cookie；所有业务接口服务端鉴权并做团队隔离；登录验证码；登录失败限流；写操作记录操作人快照 |
| 一致性 | 库存扣减/恢复、交接确认、审批必须在数据库事务中完成；库存不得为负                                                                          |
| 性能   | 常规页面首屏 < 2s（本地）；列表分页；统计查询走索引；SQLite WAL 模式                                                                       |
| 可用性 | 移动端 375px 起可用；触控目标 ≥44px；深浅色主题；表单内联校验；空/加载/错误态完备                                                          |
| 可维护 | TypeScript 全栈类型共享（oRPC）；Drizzle 迁移；文档齐全；每个里程碑 git 提交                                                               |
| 部署   | 单机 Docker Compose 部署到 1Panel；数据卷持久化；升级只替换镜像并自动迁移；提供备份/恢复说明                                               |
| 兼容   | 现代浏览器（Chrome/Edge/Safari 最近两个大版本）；扫码页适配手机浏览器                                                                      |

## 6. 术语

| 术语         | 含义                                                               |
| ------------ | ------------------------------------------------------------------ |
| 交接事项     | 一个独立的用物仓库与交接场景，拥有自己的物品目录、二维码与交接记录 |
| 交接记录     | 某交接事项在某一天的一条记录，包含接班验收与交班提交两部分         |
| 验收/接班    | 接班人核对清单并确认接收                                           |
| 交班表       | 交班人核对清单后提交的用物交接表                                   |
| 用物消耗记录 | 一次用物使用事件（患者 + 操作员 + 物品明细）                       |
| 库存流水     | 库存变化的不可变审计记录                                           |
| 撤销申请     | 对已生效消耗记录的反向操作请求，管理员审批后恢复库存               |

## 7. 边界与假设

1. 二维码由物理打印/张贴使用，系统不内置摄像头扫码；手机相机扫码后打开本站页面。
2. 交接差异的线下沟通不在系统内建聊天/工单，仅通过异常事件与库存调整留痕。
3. 时间为服务器/团队时区（默认 Asia/Shanghai）；日期以 YYYY-MM-DD 存储，避免时区漂移。
4. 库存数量为整数；如需小数单位，可在后续版本扩展为定点数。
5. 首版不提供多语言；界面为简体中文。
